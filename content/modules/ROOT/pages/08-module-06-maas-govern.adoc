= 模块 6：治理与消费 Models-as-a-Service
:navtitle: 模块 6：治理与消费 MaaS

平台搭建完成后，平台团队的日常工作是治理：提供哪些模型、面向谁、以什么速率提供，
以及每个消费者用了多少。应用团队只需要一个 URL 和一个密钥。
客户的问题是：_我如何按层级和限额向我的团队发布模型，
他们和他们的应用又该如何消费它？_

在本模块中，你将通过 MaaS 发布 llm-d 模型，定义具有不同 token 限额的两个订阅层级，
为每个层级生成一个 API 密钥，验证每个层级的限额，读取每个订阅的使用量，
并从一个只知道 URL 和密钥的应用中调用该模型。

NOTE: 此处使用的若干 Models-as-a-Service 功能在 OpenShift AI {rhoai_version} 中为
*技术预览版*；详见 xref:07-module-05-maas-standup.adoc[模块 5] 中的说明。

.第一次接触 MaaS 治理？
[%collapsible]
====
* *MaaSModelRef* — 将一个模型（此处为 `LLMInferenceService`）发布到 MaaS；与模型存放在同一命名空间。
* *MaaSSubscription* — 一个层级：哪些组可以持有它、它涵盖哪些模型，以及每个模型的 token 速率限制；
  存放在 `{maas_namespace}`。
* *MaaSAuthPolicy* — 哪些组可以调用哪些模型；存放在 `{maas_namespace}`。
* *API 密钥* — maas-api 为某个订阅颁发的 `sk-oai-…` 密钥；仅展示一次，会过期。
* *Token 速率限制* — 每个时间窗口内的 prompt 加 completion token 总预算，由 Limitador 计数。
====

== 技术背景

MaaS 调用携带一个 API 密钥。网关请求 Authorino 对其进行认证；
Authorino 询问 maas-api 该密钥属于哪个订阅，以及该订阅是否涵盖所请求的模型。
然后 Limitador 从订阅的限额中扣除响应的 token 数量，
并在窗口预算耗尽时返回 `429`。
模块 5 中的 TelemetryPolicy 将用户、订阅和模型作为标签添加到 Prometheus 收集的计数器上。
模型本身对这一切毫不知情：vLLM 的服务方式与模块 4 完全相同。

订阅和授权策略必须存放在 `{maas_namespace}`（maas-api 读取的命名空间）中；
`MaaSModelRef` 存放在模型的项目中并指向模型。

== 学习目标

* 将模型连接到 MaaS 网关，并使用 `MaaSModelRef` 发布它。
* 使用 `MaaSSubscription` 定义两个层级，并使用 `MaaSAuthPolicy` 授予访问权限。
* 生成 API 密钥并按路径调用模型；验证无密钥时返回 401。
* 验证不同层级具有不同的 token 限额（429），并读取每个订阅的使用量。
* 从一个只使用 OpenAI SDK、URL 和密钥的应用中消费该模型。

== 练习 1：将模型切换到 MaaS 网关

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m6-ex1.mp4[width=100%]

`LLMInferenceService` 必须连接到 `{maas_gateway}`，
且 vLLM 必须始终报告 token 使用量（`--enable-force-include-usage`），
供 Limitador 计数。更改 Pod 规格会滚动 Deployment，
并短暂需要 GPU 上运行第三个 vLLM，因此改为重新创建：

[source,bash,role="execute",subs="attributes+"]
----
oc delete llminferenceservice {model_name} -n {model_namespace} --wait=true
oc apply -n {model_namespace} -f - <<'EOF'
apiVersion: serving.kserve.io/v1alpha2
kind: LLMInferenceService
metadata:
  name: {model_name}
spec:
  replicas: 2
  model:
    uri: {model_uri}
    name: {model_name}
  router:
    gateway:
      refs:
      - name: {maas_gateway}
        namespace: openshift-ingress
    route: {}
    scheduler: {}
  template:
    tolerations: [{key: nvidia.com/gpu, operator: Exists, effect: NoSchedule}]
    resourceClaims:
    - name: gpu
      resourceClaimName: shared-l4
    containers:
    - name: main
      env:
      - name: VLLM_ADDITIONAL_ARGS
        value: "{vllm_shared_args} --enable-force-include-usage"
      resources:
        requests: {cpu: "1", memory: 8Gi}
        limits: {cpu: "3", memory: 12Gi}
        claims: [{name: gpu}]
EOF
oc wait llminferenceservice/{model_name} -n {model_namespace} --for=condition=Ready --timeout=900s
oc get llminferenceservice {model_name} -n {model_namespace} -o jsonpath='{.status.url}{"\n"}'
----

预期结果：几分钟后显示 `condition met`，URL 现在变为
`https://maas.{cluster_domain}/{model_namespace}/{model_name}`。

== 练习 2：发布模型并设置两个层级

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m6-ex2.mp4[width=100%]

[source,yaml,subs="attributes+"]
----
kind: MaaSSubscription
metadata:
  name: granite-bronze
  namespace: {maas_namespace}                       # <1>
spec:
  owner:
    groups: [{name: "system:authenticated:oauth"}]  # <2>
  tokenMetadata: {costCenter: field-enablement, organizationId: korea-gps}   # <3>
  modelRefs:
  - name: {model_name}
    namespace: {model_namespace}
    tokenRateLimits: [{limit: 300, window: 1m}]     # <4>
----
<1> *namespace* — 订阅只从 `{maas_namespace}` 读取。
<2> *owner.groups* — 谁可以持有此层级；`system:authenticated:oauth` 表示任何通过 OAuth 登录的用户（普通的 `system:authenticated` 也匹配 ServiceAccount）。
<3> *tokenMetadata* — 出现在使用量指标上的成本归属标签。
<4> *tokenRateLimits* — 该模型每分钟 300 个 token；金级层级获得 20,000 个。

[source,bash,role="execute",subs="attributes+"]
----
oc apply -f - <<'EOF'
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSModelRef
metadata:
  name: {model_name}
  namespace: {model_namespace}
spec:
  modelRef:
    kind: LLMInferenceService
    name: {model_name}
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSSubscription
metadata:
  name: granite-gold
  namespace: {maas_namespace}
spec:
  owner:
    groups: [{name: "system:authenticated:oauth"}]
  tokenMetadata: {costCenter: field-enablement, organizationId: korea-gps}
  modelRefs:
  - name: {model_name}
    namespace: {model_namespace}
    tokenRateLimits: [{limit: 20000, window: 1m}]
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSSubscription
metadata:
  name: granite-bronze
  namespace: {maas_namespace}
spec:
  owner:
    groups: [{name: "system:authenticated:oauth"}]
  tokenMetadata: {costCenter: field-enablement, organizationId: korea-gps}
  modelRefs:
  - name: {model_name}
    namespace: {model_namespace}
    tokenRateLimits: [{limit: 300, window: 1m}]
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSAuthPolicy
metadata:
  name: granite-access
  namespace: {maas_namespace}
spec:
  subjects:
    groups: [{name: "system:authenticated:oauth"}]
  modelRefs:
  - name: {model_name}
    namespace: {model_namespace}
EOF
sleep 20
oc get maasmodelref {model_name} -n {model_namespace}
oc get maasmodelref {model_name} -n {model_namespace} -o jsonpath='{range .status.conditions[*]}{.type}={.status}: {.message}{"\n"}\{end}'
oc get maassubscription,maasauthpolicy -n {maas_namespace}
----

预期结果：MaaSModelRef 状态为 `Ready`，端点为 `https://maas.{cluster_domain}/`，
HTTPRoute 为 `{model_name}-kserve-route`，网关为 `{maas_gateway}`；
其条件包括 `GovernanceAttached=True: Active governance pairing found`
和 `RuntimeReady=True: Backend is healthy`；两个订阅和授权策略均为 `Active`。

界面视图：在 OpenShift AI 控制台中，*Settings* → *MaaS governance*，
选项卡 *Subscriptions*：`granite-bronze` 和 `granite-gold`，状态 `Ready`，
各有一个组和一个模型。该页面的 *Create subscription* 按钮会写入与你刚应用的相同的 `MaaSSubscription`。

image::08-maas-governance.png[MaaS 治理页面，列出 granite-bronze 和 granite-gold 订阅，状态为 Ready]

== 练习 3：生成密钥并调用模型

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m6-ex3.mp4[width=100%]

[source,bash,role="execute",subs="attributes+"]
----
{ cat /etc/pki/tls/certs/ca-bundle.crt; oc get configmap default-ingress-cert -n openshift-config-managed -o jsonpath='{.data.ca-bundle\.crt}'; } > ~/ingress-ca.crt
export CURL_CA_BUNDLE=~/ingress-ca.crt
DOMAIN=$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}'); MAAS=https://maas.$DOMAIN
for tier in gold bronze; do
  # The first call after the policies attach can return nothing; try three times.
  for try in 1 2 3; do
    resp=$(curl -s --max-time 30 -X POST "$MAAS/maas-api/v1/api-keys" -H "Authorization: Bearer $(oc whoami -t)" -H 'Content-Type: application/json' \
      -d "{\"name\":\"workshop-$tier\",\"expiresIn\":\"72h\",\"subscription\":\"granite-$tier\"}")
    key=$(jq -r '.key // empty' <<<"$resp" 2>/dev/null)
    [ -n "$key" ] && break; sleep 5
  done
  case "$key" in
    sk-oai-*) printf '%s' "$key" > ~/key-$tier; echo "$tier key: $(cut -c1-10 ~/key-$tier)…, expires $(jq -r '.expiresAt // "?"' <<<"$resp")" ;;
    *) echo "$tier: minting failed, existing key kept: $resp" ;;
  esac
done
curl -s "$MAAS/maas-api/v1/models" -H "Authorization: Bearer $(cat ~/key-gold)" | jq -r '.data[].id'
CHAT="$MAAS/{model_namespace}/{model_name}/v1/chat/completions"
curl -s "$CHAT" -H "Authorization: Bearer $(cat ~/key-gold)" -H 'Content-Type: application/json' \
  -d '{"model": "{model_name}", "messages": [{"role": "user", "content": "One word: capital of Korea?"}], "max_tokens": 10}' \
  | jq -c '{answer: .choices[0].message.content, usage}'
curl -s -o /dev/null -w 'no key: %\{http_code}\n' "$CHAT" -H 'Content-Type: application/json' \
  -d '{"model": "{model_name}", "messages": [{"role": "user", "content": "hi"}]}'
----

预期结果：两个以 `sk-oai-` 开头的密钥，各自在 72 小时后过期（`expiresIn: 72h`，可用到第 3 天）；
模型列表显示 `publishers/{model_namespace}/models/{model_name}`；
聊天调用返回带有 `usage` 字段（prompt 和 completion token 数）的响应；
以及 `no key: 401`。
密钥存储在 Web Terminal 的主目录中；maas-api 不会再次展示它们。
若生成失败则打印 `minting failed` 并保留已保存的密钥。
Web Terminal 的主目录在终端重启后不会保留：若 `~/key-gold` 丢失，请重新运行此代码块生成新密钥。

== 练习 4：层级限额是真实的（429）

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m6-ex4.mp4[width=100%]

用每个密钥发送同样的 12 个请求：

[source,bash,role="execute",subs="attributes+"]
----
for tier in bronze gold; do
  printf '%-7s' "$tier:"
  for i in $(seq 1 12); do
    curl -s -o /dev/null -w '%\{http_code} ' "$CHAT" -H "Authorization: Bearer $(cat ~/key-$tier)" -H 'Content-Type: application/json' \
      -d '{"model": "{model_name}", "messages": [{"role": "user", "content": "Write one sentence about GPUs."}], "max_tokens": 40}'
  done; echo
done
----

预期结果：`bronze: 200 200 200 200 200 429 429 429 429 429 429 429`
（前五个请求消耗约 300 个 token，然后该窗口的预算耗尽），以及 `gold:` 十二个 `200`。
同一个模型，同一个网关，不同的合约。等待一分钟后，bronze 层级的请求将再次被处理。

== 练习 5：读取每个订阅的使用量

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m6-ex5.mp4[width=100%]

查询集群的 Prometheus（Thanos querier）以获取 Limitador 导出的计数器：

[source,bash,role="execute"]
----
Q=https://$(oc get route thanos-querier -n openshift-monitoring -o jsonpath='{.spec.host}')/api/v1/query
for promql in 'sum by (subscription, user) (authorized_hits)' 'sum by (subscription) (authorized_calls)' 'sum(limited_calls)'; do
  echo "$promql"
  curl -s -G -H "Authorization: Bearer $(oc whoami -t)" "$Q" --data-urlencode "query=$promql" \
    | jq -r '.data.result[] | "   \(.metric.subscription // "-") \(.metric.user // "-")  \(.value[1])"'
done
----

预期结果：`authorized_hits`（扣除的 token 数）显示 `granite-gold` 和 `granite-bronze` 以及你的用户名；
`authorized_calls`（请求数）按订阅显示；`limited_calls` 计算 `429` 的次数。
这是按成本中心进行成本归属的原始数据。

界面视图：在 OpenShift 控制台中，*Observe* → *Metrics*，
输入 `sum by (subscription) (authorized_hits)` 并点击 *Run queries*：
每个订阅显示一行及其 token 计数。

image::08-observe-metrics.png[Metrics 页面，显示按订阅汇总的 authorized_hits，包含 granite-bronze 和 granite-gold]

== 练习 6：从应用中消费模型

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m6-ex6.mp4[width=100%]

应用只需要三样东西：base URL、模型名称和密钥，以及对网关证书的信任。
此 Job 使用 OpenAI Python SDK 通过金级密钥访问 MaaS（密钥从 Secret 挂载），
并使用签署集群默认 ingress 证书的 CA（由 OpenShift 通过 `default-ingress-cert` ConfigMap 发布）
来验证网关：

[source,bash,role="execute",subs="attributes+"]
----
oc create secret generic maas-key -n {model_namespace} --from-literal=api-key="$(cat ~/key-gold)" --dry-run=client -o yaml | oc apply -f -
oc create configmap ingress-ca -n {model_namespace} --from-file=ca.crt=$HOME/ingress-ca.crt --dry-run=client -o yaml | oc apply -f -
oc delete job maas-client -n {model_namespace} --ignore-not-found --wait=true
oc apply -n {model_namespace} -f - <<EOF
apiVersion: batch/v1
kind: Job
metadata:
  name: maas-client
spec:
  backoffLimit: 0
  template:
    spec:
      restartPolicy: Never
      containers:
      - name: app
        image: image-registry.openshift-image-registry.svc:5000/redhat-ods-applications/s2i-minimal-notebook:{rhoai_version}
        env:
        - {name: BASE_URL, value: "$MAAS/{model_namespace}/{model_name}/v1"}
        - {name: API_KEY, valueFrom: {secretKeyRef: {name: maas-key, key: api-key}}}
        volumeMounts: [{name: ingress-ca, mountPath: /etc/ingress-ca}]
        command: ["bash", "-c"]
        args:
        - |
          pip install -q openai >/dev/null 2>&1
          python - <<'PY'
          import os, httpx
          from openai import OpenAI
          c = OpenAI(base_url=os.environ["BASE_URL"], api_key=os.environ["API_KEY"], http_client=httpx.Client(verify="/etc/ingress-ca/ca.crt"))
          r = c.chat.completions.create(model="{model_name}", messages=[{"role": "user", "content": "Name one benefit of an internal model service."}], max_tokens=60)
          print("ANSWER:", r.choices[0].message.content.strip())
          print("USAGE:", r.usage.prompt_tokens, "prompt +", r.usage.completion_tokens, "completion tokens")
          PY
      volumes: [{name: ingress-ca, configMap: {name: ingress-ca}}]
EOF
oc wait job/maas-client -n {model_namespace} --for=condition=Complete --timeout=300s
oc logs job/maas-client -n {model_namespace} | grep -E 'ANSWER|USAGE'
----

预期结果：`condition met`，然后显示一行 `ANSWER:` 和一行带有 token 数量的 `USAGE:`。
应用从未接触过 OpenShift token、GPU 或 Kubernetes 对象：只有 URL、密钥和受信任的 CA。

== 检查点

继续之前，请验证你能回答以下问题：

* 哪个对象与模型存放在一起，哪些存放在 `{maas_namespace}` 中，为什么？
* 当第六个 bronze 请求返回 429 时，逐步发生了什么？
* `authorized_hits` 上的 `subscription` 标签来自哪里？
* 应用消费 MaaS 模型需要什么？

.参考答案
[%collapsible]
====
* `MaaSModelRef` 存放在模型的项目中并指向模型；`MaaSSubscription` 和 `MaaSAuthPolicy`
  存放在 `{maas_namespace}`，这是 maas-api 唯一读取它们的命名空间。
* 网关请求 Authorino 认证该密钥（有效，订阅为 `granite-bronze`），
  然后请求 Limitador 准许该请求；该订阅本分钟的 300 token 预算已被前五个响应耗尽，
  因此 Limitador 拒绝，网关返回 429 而不调用 vLLM。
* 来自 TelemetryPolicy：它用 `auth.identity.selected_subscription`（Authorino 为该密钥解析出的订阅）
  标记 Limitador 的计数器。
* base URL（`https://maas.<domain>/<project>/<model>/v1`）、模型名称和 API 密钥。
====
