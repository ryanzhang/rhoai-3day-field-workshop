= 模块 9：使用 NeMo Guardrails 保护模型
:navtitle: 模块 9：使用 NeMo Guardrails 保护模型

评估告诉你模型的平均表现有多好。但它不能阻止那一条请求有害内容的 prompt，也无法拦截泄露社会安全号码的请求。客户需要在模型前面设置一个控制层，逐请求决定什么可以通过，并且他们需要知道它拦截了什么、错误地阻止了什么、以及它的开销是多少。客户的问题：_我们如何阻止有害或敏感请求，以及如何证明控制措施有效？_

在本模块中，你将在认证保护下部署 NeMo Guardrails，比较简单的正则表达式规则与 LLM 评判器（你的 Granite 模型）对相同 prompt 的处理结果，对两者进行精确率和召回率测量，观察评判器不可达时的行为，并发现并关闭途中存在的一条通往模型的开放路径。

.初次接触 Guardrail？
[%collapsible]
====
* *NeMo Guardrails* — 一个对输入和输出运行 *rail*（检查）的服务器；OpenShift AI 通过 `NemoGuardrails` 资源（TrustyAI）部署它。
* *Rail configuration（规则配置）* — 一组带设置的 rail，存储在 ConfigMap 中；请求通过 `guardrails.config_id` 选择配置。
* *Regex rail（正则表达式规则）* — 阻止匹配模式的文本；速度快且可预测，但对语义不敏感。
* *Self-check input（自检输入）* — 将用户消息包裹在你编写的策略中发给 LLM，如果 LLM 回答 *yes* 则阻止该请求。
* *Precision / Recall（精确率/召回率）* — 在被阻止的内容中，有多少应该被阻止；在应该被阻止的内容中，有多少实际被阻止了。
====

== 技术背景

Guardrail 服务器的 `/v1/guardrail/checks` 端点在不调用主模型生成答案的情况下，逐条返回每个 rail 的判定，从而单独衡量 rail 的效果。认证在创建时通过 `security.opendatahub.io/enable-auth: "true"` 开启：此后 kube-rbac-proxy 要求调用者拥有在项目中 `get services` 的 token。

评判器是你的 Granite 模型。Guardrail 服务器在集群内部调用它，使用 llm-d 工作负载 Service：`https://{model_name}-kserve-workload-svc.{model_namespace}.svc.cluster.local:8000/v1`，该 Service 的证书由 OpenShift Service CA 签发，所有 OpenShift AI 工作负载自动信任。该 Service 本身没有认证：MaaS 只保护前门。练习 6 会处理这个问题。

NOTE: 如果 Ingress 证书是公开受信任的，评判器也可以使用自己的 API 密钥调用 MaaS 端点，像其他任何消费者一样被计费。在自签名 Ingress 证书的集群上，Guardrail 服务器无法在不改变集群级别信任的情况下信任该 CA。

== 学习目标

* 部署带认证的 Guardrail 服务器并配置正则表达式规则，证明谁可以调用它。
* 添加 LLM 评判器规则，对相同的 prompt（包括陷阱）比较两种规则。
* 在带标签的测试集上测量两种规则的精确率和召回率，以及它们的延迟。
* 演示评判器不可达时 Guardrail 的响应，以及为什么这很重要（开放失败还是关闭失败）。
* 找到一条通往模型的未认证路径，并用 NetworkPolicy 关闭它。

== 练习 1：带正则表达式规则的受保护端点

.视频：在测试集群上运行本练习（等待时间已加速）
video::m9-ex1.mp4[width=100%]

[source,bash,role="execute"]
----
oc new-project ws-guard >/dev/null 2>&1 || oc project ws-guard
oc apply -n ws-guard -f - <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: regex-only
data:
  config.yaml: |
    rails:
      config:
        regex_detection:
          input:
            patterns:
              - '\b\d{3}-\d{2}-\d{4}\b'
              - '\b(?:\d{4}[- ]?){3}\d{4}\b'
              - '(?i)\b(password|api[_-]?key|token|secret)\b'
              - '(?i)\b(bomb|weapon|explosive)\b'
      input:
        flows:
          - regex check input
  rails.co: |
    # Built-in flows only.
---
apiVersion: trustyai.opendatahub.io/v1alpha1
kind: NemoGuardrails
metadata:
  name: nemoguardrails
  annotations:
    security.opendatahub.io/enable-auth: "true"
spec:
  nemoConfigs:
  - name: regex-only
    configMaps: [regex-only]
    default: true
EOF
----

待部署完成后（约 2 分钟），通过三种方式调用 `/v1/guardrail/checks` 端点：不带 token、带 token、发送包含社会安全号码的请求：

[source,bash,role="execute"]
----
until oc get route nemoguardrails -n ws-guard >/dev/null 2>&1; do sleep 5; done
GR=https://$(oc get route nemoguardrails -n ws-guard -o jsonpath='{.spec.host}')
H=(-H "Authorization: Bearer $(oc whoami -t)")
curl -s -o /dev/null -w 'no token: %{http_code}\n' -X POST "$GR/v1/guardrail/checks" -H 'Content-Type: application/json' -d '{"messages":[{"role":"user","content":"hello"}]}'
curl -s -o /dev/null -w 'with token, benign: %{http_code}\n' "${H[@]}" -X POST "$GR/v1/guardrail/checks" -H 'Content-Type: application/json' -d '{"messages":[{"role":"user","content":"hello"}]}'
curl -s "${H[@]}" -X POST "$GR/v1/guardrail/checks" -H 'Content-Type: application/json' -d '{"messages":[{"role":"user","content":"my SSN is 123-45-6789"}]}' | jq '{blocked: .blocked, rails: [.rails[] | {name, triggered}]}'
----

预期结果：`no token: 401`；`with token, benign: 200`（`blocked: false`）；以及带社会安全号码的请求被正则表达式规则拦截（`blocked: true`，`triggered: true`）。

注意：其余练习（2-6）涵盖：LLM 评判器配置与比较、精确率/召回率测量、评判器故障场景、发现并关闭未认证路径（NetworkPolicy）。请参考英文原版进行操作。
