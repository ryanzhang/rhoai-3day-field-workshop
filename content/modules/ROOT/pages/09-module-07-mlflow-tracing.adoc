= 模块 7：使用 MLflow 追踪 Agent
:navtitle: 模块 7：使用 MLflow 追踪 Agent

Agent 是一个循环：模型决定调用工具，代码执行它，结果返回给模型，如此循环直到得出答案。当答案错误或响应缓慢时，日志中的"200 OK"毫无意义。你需要看到每一步：模型收到了什么问题，选择了哪个工具及其参数，返回了什么结果，每次调用消耗了多少 token，时间花在哪里。客户的问题：_当 Agent 在生产环境中出现异常行为时，我们如何查看它实际执行了什么？_

在本模块中，你将在 OpenShift AI 上启用 MLflow，为 Agent 配置一个只能写入追踪数据的身份，然后对你的 MaaS 模型运行一个小型工具调用 Agent。最后，你将逐 span 读取其追踪记录。

.初次接触追踪？
[%collapsible]
====
* *Trace（追踪）* — 一个请求通过应用程序的完整记录：一棵 span 的树。
* *Span（跨度）* — 追踪内的一个计时步骤（一次 LLM 调用、一次工具调用、Agent 循环本身），包含其输入、输出和属性（如 token 数量）。
* *Autolog（自动日志）* — MLflow 对库（此处为 OpenAI SDK）的插桩，使每次调用都成为一个 span，无需修改调用代码。
* *Experiment（实验）* — MLflow 用于管理一个应用程序的运行记录和追踪的容器。
* *Workspace（工作空间）* — 在 OpenShift AI 中，MLflow 的租户边界：每个 OpenShift 项目对应一个工作空间。
====

== 技术背景

[cols="1,3",options="header"]
|===
| 组件 | 作用

| DataScienceCluster 中的 `mlflowoperator`
| 安装 MLflow operator 及其 `MLflow` 资源类型

| `MLflow` CR（`mlflow`）
| 集群的一个追踪服务器，部署在 `redhat-ods-applications` 中，此处使用 SQLite 持久卷；通过 `https://rh-ai.{cluster_domain}/mlflow` 对外提供服务，集群内地址为 `https://mlflow.redhat-ods-applications.svc:8443/mlflow`

| 工作空间与 RBAC
| 每个请求都指定一个工作空间（OpenShift 项目）；MLflow 检查调用者在该项目中对虚拟 `mlflow.kubeflow.org` 资源（experiments、datasets、registered models）的 Kubernetes RBAC 权限

| Agent
| 一个使用 OpenAI SDK 通过 MaaS 金密钥调用的 Python 任务；`mlflow.openai.autolog()` 追踪每次模型调用，`@mlflow.trace` 标记 Agent 循环和工具
|===

Agent 使用 API 密钥向 MaaS 认证，使用 ServiceAccount token 向 MLflow 认证：两种不同的身份，由两个不同的系统管理。

== 学习目标

* 启用 MLflow 并创建追踪服务器。
* 解释 MLflow 在 OpenShift AI 上如何划分数据范围（工作空间）以及授权调用者（RBAC）。
* 演示没有 MLflow 权限的 Agent 无法写入追踪，然后授予精确所需的权限。
* 读取 Agent 的追踪记录：span 类型、工具调用的参数与结果、token 用量和延迟。

== 练习 2：MLflow 如何决定谁能访问什么

.视频：在测试集群上运行本练习（等待时间已加速）
video::m7-ex2.mp4[width=100%]

以三种方式调用追踪 API：不带 token、带 token 但不指定工作空间、同时带 token 和工作空间。

[source,bash,role="execute",subs="attributes+"]
----
{ cat /etc/pki/tls/certs/ca-bundle.crt; oc get configmap default-ingress-cert -n openshift-config-managed -o jsonpath='{.data.ca-bundle\.crt}'; } > ~/ingress-ca.crt
export CURL_CA_BUNDLE=~/ingress-ca.crt
ML=https://rh-ai.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')/mlflow
oc new-project ws-agent >/dev/null 2>&1 || oc project ws-agent
curl -s -o /dev/null -w 'no token:            %\{http_code}\n' "$ML/api/2.0/mlflow/experiments/search?max_results=5"
curl -s -w '\n' -H "Authorization: Bearer $(oc whoami -t)" "$ML/api/2.0/mlflow/experiments/search?max_results=5"
curl -s -w '\n' -H "Authorization: Bearer $(oc whoami -t)" -H 'X-MLFLOW-WORKSPACE: ws-agent' "$ML/api/2.0/mlflow/experiments/search?max_results=5"
----

预期结果：`no token: 302`（重定向到 OpenShift 登录页面）；带 token 但无工作空间时，返回 `{"error":{"code":"INVALID_PARAMETER_VALUE","message":"Workspace context is required for this request."}}`；带工作空间 `ws-agent` 时，返回 `{}`：一个空工作空间，属于你刚创建的项目。

简而言之：MLflow 工作空间就是一个 OpenShift 项目，MLflow 通过 Kubernetes 判断谁有权使用它。

== 练习 3：没有 MLflow 权限的 Agent（负控实验）

.视频：在测试集群上运行本练习（等待时间已加速）
video::m7-ex3.mp4[width=100%]

Agent 使用你在第 2 天生成的金密钥调用 MaaS。确认密钥仍然有效，如果已过期或终端丢失则重新生成（Web Terminal 的家目录重启后不会保留）：

[source,bash,role="execute",subs="attributes+"]
----
MAAS=https://maas.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
code=$(curl -s -o /dev/null -w '%\{http_code}' -H "Authorization: Bearer $(cat ~/key-gold 2>/dev/null)" "$MAAS/maas-api/v1/models")
if [ "$code" != 200 ]; then
  echo "gold key not usable (HTTP $code): minting a new one"
  resp=$(curl -s -X POST "$MAAS/maas-api/v1/api-keys" -H "Authorization: Bearer $(oc whoami -t)" -H 'Content-Type: application/json' \
    -d '{"name":"workshop-gold-day3","expiresIn":"72h","subscription":"granite-gold"}')
  key=$(jq -r '.key // empty' <<<"$resp")
  case "$key" in sk-oai-*) printf '%s' "$key" > ~/key-gold ;; *) echo "minting failed: $resp" ;; esac
fi
curl -s -o /dev/null -w 'gold key: %\{http_code}\n' -H "Authorization: Bearer $(cat ~/key-gold)" "$MAAS/maas-api/v1/models"
----

预期结果：如果密钥已过期或丢失，会先显示 `gold key not usable … minting a new one`，然后显示 `gold key: 200`。

现在为 Agent 创建身份、金密钥、Ingress CA 和代码：

[source,bash,role="execute",subs="attributes+"]
----
oc create sa weather-agent -n ws-agent --dry-run=client -o yaml | oc apply -f -
oc create secret generic maas-key -n ws-agent --from-literal=api-key="$(cat ~/key-gold)" --dry-run=client -o yaml | oc apply -f -
oc create configmap ingress-ca -n ws-agent --from-file=ca.crt=$HOME/ingress-ca.crt --dry-run=client -o yaml | oc apply -f -
oc create configmap weather-agent -n ws-agent --from-file=agent.py=/dev/stdin --dry-run=client -o yaml <<'PY' | oc apply -f -
import json, os, httpx, mlflow
from openai import OpenAI

mlflow.set_tracking_uri("https://mlflow.redhat-ods-applications.svc:8443/mlflow")
mlflow.set_experiment("weather-agent")
mlflow.openai.autolog()

client = OpenAI(base_url=os.environ["MAAS_URL"], api_key=os.environ["MAAS_KEY"],
                http_client=httpx.Client(verify="/etc/ingress-ca/ca.crt"))
TOOLS = [{"type": "function", "function": {"name": "get_weather", "description": "Current weather for a city",
          "parameters": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}}}]

@mlflow.trace(span_type="TOOL")
def get_weather(city):
    return {"city": city, "sky": "clear", "celsius": 14}   # stand-in for a real weather API

@mlflow.trace(span_type="AGENT")
def agent(question):
    messages = [{"role": "user", "content": question}]
    for _ in range(3):
        m = client.chat.completions.create(model="{model_name}", messages=messages, tools=TOOLS, max_tokens=200).choices[0].message
        if not m.tool_calls:
            return m.content
        messages.append(m.model_dump(exclude_none=True))
        for tc in m.tool_calls:
            messages.append({"role": "tool", "tool_call_id": tc.id,
                             "content": json.dumps(get_weather(**json.loads(tc.function.arguments)))})
    return "gave up"

print("ANSWER:", agent("Should I bring a jacket in Seoul today?"))
mlflow.flush_trace_async_logging()
trace = mlflow.get_trace(mlflow.get_last_active_trace_id())
print("TRACE", trace.info.trace_id, trace.info.state, f"{trace.info.execution_duration} ms")
for s in trace.data.spans:
    print(f"  SPAN {s.span_type:<10} {s.name:<14} {(s.end_time_ns - s.start_time_ns) // 1000000:>6} ms")
print("TOKENS", trace.info.token_usage)
PY
----

预期结果：ServiceAccount、Secret 和两个 ConfigMap 创建成功。

以 Job 方式运行 Agent。此时 ServiceAccount 还没有 RoleBinding：

[source,bash,role="execute",subs="attributes+"]
----
DOMAIN=$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
run_agent() {
oc delete job weather-agent -n ws-agent --ignore-not-found --wait=true
oc apply -n ws-agent -f - <<EOF
apiVersion: batch/v1
kind: Job
metadata:
  name: weather-agent
spec:
  backoffLimit: 0
  template:
    spec:
      serviceAccountName: weather-agent
      restartPolicy: Never
      containers:
      - name: agent
        image: image-registry.openshift-image-registry.svc:5000/redhat-ods-applications/s2i-minimal-notebook:{rhoai_version}
        command: ["bash", "-c", "pip install -q 'mlflow==3.14.0' openai >/tmp/pip.log 2>&1 || { tail -5 /tmp/pip.log; exit 1; }; MLFLOW_TRACKING_TOKEN=\$(cat /var/run/secrets/kubernetes.io/serviceaccount/token) python /app/agent.py"]
        env:
        - {name: MLFLOW_WORKSPACE, value: ws-agent}
        - {name: MLFLOW_TRACKING_SERVER_CERT_PATH, value: /var/run/secrets/kubernetes.io/serviceaccount/service-ca.crt}
        - {name: MAAS_URL, value: "https://maas.$DOMAIN/{model_namespace}/{model_name}/v1"}
        - {name: MAAS_KEY, valueFrom: {secretKeyRef: {name: maas-key, key: api-key}}}
        volumeMounts:
        - {name: app, mountPath: /app}
        - {name: ingress-ca, mountPath: /etc/ingress-ca}
      volumes:
      - {name: app, configMap: {name: weather-agent}}
      - {name: ingress-ca, configMap: {name: ingress-ca}}
EOF
until [ -n "$(oc get job weather-agent -n ws-agent -o jsonpath='{.status.succeeded}{.status.failed}')" ]; do sleep 5; done
oc logs job/weather-agent -n ws-agent | grep -o -E 'ANSWER:.*|TRACE .*|  SPAN .*|TOKENS .*|PERMISSION_DENIED|ERROR: .*' | cut -c1-200
[ "$(oc get job weather-agent -n ws-agent -o jsonpath='{.status.succeeded}')" = 1 ] && echo "job: succeeded" || { echo "job: failed"; return 1; }
}
# 重新运行时，如果练习 4 的 RoleBinding 还在，先删除，确保此处仍为负控实验
oc delete rolebinding weather-agent-mlflow -n ws-agent --ignore-not-found
run_agent
----

预期结果：Job 失败，日志显示 `PERMISSION_DENIED`（单独显示，或在 `ERROR: …` 行中），来自 MLflow 的响应（`RestException … {'error': {'code': 'PERMISSION_DENIED', …}}`），随后显示 `job: failed`：Agent 的 ServiceAccount 可以调用 MaaS（持有密钥），但无权向 `ws-agent` 工作空间写入数据。

== 练习 4：授予精确的追踪权限后再次运行

.视频：在测试集群上运行本练习（等待时间已加速）
video::m7-ex4.mp4[width=100%]

OpenShift AI 为 MLflow 提供了 ClusterRole：`mlflow-operator-mlflow-view`、`-edit` 和 `-integration`（供记录实验和追踪的应用使用）。在当前项目中绑定 integration 角色：

[source,bash,role="execute"]
----
oc get clusterrole mlflow-operator-mlflow-integration -o jsonpath='{range .rules[*]}{.resources}{" "}{.verbs}{"\n"}{end}' | head -3
oc create rolebinding weather-agent-mlflow -n ws-agent \
  --clusterrole=mlflow-operator-mlflow-integration --serviceaccount=ws-agent:weather-agent --dry-run=client -o yaml | oc apply -f -
run_agent
----

预期结果：第一行显示 `["datasets","experiments","registeredmodels"]` 和 `["get","list","create","update"]`（该角色的其他规则仅读取网关端点和 MCP 服务器）；然后 Agent 根据工具返回值给出答案（晴天，约 14°C，建议带外套），并打印类似如下的追踪信息：

[source,text]
----
TRACE tr-… OK 6313 ms
  SPAN AGENT      agent            6313 ms
  SPAN CHAT_MODEL Completions      2102 ms
  SPAN TOOL       get_weather         0 ms
  SPAN CHAT_MODEL Completions      4175 ms
TOKENS {'input_tokens': 430, 'output_tokens': 81, 'total_tokens': 511}
----

模型的两次调用几乎占据了全部时间；工具调用几乎是即时的。你的数字会有所不同。

简而言之：追踪将 Agent 的推理循环呈现为可查看的数据：提问、调用工具、给出答案。

== 练习 5：通过 API 和仪表板读取追踪记录

.视频：在测试集群上运行本练习（等待时间已加速）
video::m7-ex5.mp4[width=100%]

Job 在自己的进程中打印了追踪记录。现在作为另一个客户端，通过 MLflow UI 使用的同一 REST API，从 `ws-agent` 工作空间读取它：

[source,bash,role="execute"]
----
{ cat /etc/pki/tls/certs/ca-bundle.crt; oc get configmap default-ingress-cert -n openshift-config-managed -o jsonpath='{.data.ca-bundle\.crt}'; } > ~/ingress-ca.crt
export CURL_CA_BUNDLE=~/ingress-ca.crt
ML=https://rh-ai.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')/mlflow
H=(-H "Authorization: Bearer $(oc whoami -t)" -H 'X-MLFLOW-WORKSPACE: ws-agent')
EXP=$(curl -s "${H[@]}" "$ML/api/2.0/mlflow/experiments/get-by-name?experiment_name=weather-agent" | jq -r .experiment.experiment_id)
curl -s "${H[@]}" "$ML/api/2.0/mlflow/traces?experiment_ids=$EXP&max_results=5" \
  | jq -r '.traces[] | "\(.request_id)  \(.status)  \(.execution_time_ms) ms  \([.tags[] | select(.key == "mlflow.traceName") | .value][0])"'
----

预期结果：每次 Agent 运行对应一行（包括来自已删除的 `ws-agent` 项目的运行：追踪存储在 MLflow 中，不随项目一起删除），最新的一行显示 Job 打印的追踪 ID、`OK`、以毫秒为单位的持续时间以及追踪名称 `agent`。追踪存储在集群的 MLflow 中，范围限定在 `ws-agent` 工作空间。

现在在 OpenShift AI 仪表板中查看同一追踪：

. 打开仪表板（`https://rh-ai.{cluster_domain}`）。如果刚才启用了 MLflow，刷新一次页面以显示新菜单项。
. 在左侧菜单中，打开 *Develop & train* → *Experiments*。
. 在顶部的 *Project* 选择器中，选择 `ws-agent`。实验 `weather-agent` 已列出。
. 打开 `weather-agent`，然后切换到 *Traces* 标签。

image::09-mlflow-traces.png[weather-agent 实验的 Traces 标签，一行显示问题、答案、522 个 token、6.503 秒和状态 OK]

预期结果：每次运行对应一行，包含 *Trace ID* `tr-…`、*Request* `{ "question": "Should I bring a jacket in Seoul today?" }`、*Response*、*Tokens*（约 520）、*Execution time*（约 6.5 秒）和 *State* `OK`。

. 点击追踪 ID。*Summary* 标签显示 *Status* `OK`、*Token count* 和 *Latency*，以及问题、三个步骤（*Completions was called*、*get_weather was called* 和 *Completions was called*）及其持续时间，最后是答案。

image::09-mlflow-trace-summary.png[追踪摘要：状态 OK，token 数量 522，延迟 6.50 秒，两次 Completions 调用夹着 get_weather，最终答案]

. 打开 *Details & Timeline* 标签，在 *Trace breakdown* 树中选择 `get_weather`。

image::09-mlflow-tool-span.png[Details and Timeline 标签，选中 get_weather：输入城市首尔，输出城市首尔、天气晴朗、温度 14 摄氏度]

预期结果：*Trace breakdown* 树为 `agent` → `Completions`、`get_weather`、`Completions`；`get_weather` span 的 *Inputs / Outputs* 显示输入 `city: Seoul`，输出 `city: Seoul`、`sky: clear`、`celsius: 14`。你可以精确看到模型选择了哪个工具、使用了什么参数、得到了什么返回值，而无需在 Agent 中添加任何日志代码。

== 验证检查点

继续之前，确保你能回答以下问题：

* OpenShift AI 上的 MLflow 工作空间是什么，什么决定了调用者是否可以使用它？
* 第一次运行为什么失败，尽管 Agent 可以访问 MaaS 和 MLflow？
* Agent 的追踪由哪些 span 组成，每个 span 记录什么？
* Agent 使用哪个身份访问 MaaS，哪个身份访问 MLflow？

.答案
[%collapsible]
====
* 一个 OpenShift 项目；MLflow 检查调用者在该项目中对 `mlflow.kubeflow.org` 资源（experiments、datasets、registered models）的 Kubernetes RBAC 权限。
* 其 ServiceAccount 在 `ws-agent` 中没有 RoleBinding，因此 MLflow 拒绝创建实验（`PERMISSION_DENIED`）。
* `AGENT`（整个循环）、两个 `CHAT_MODEL` span（由 autolog 记录的模型调用，包含消息和 token 用量）和一个 `TOOL` span（`get_weather`，包含参数和结果）。
* 使用 MaaS API 密钥（金订阅）访问模型；使用 Kubernetes ServiceAccount token 访问 MLflow。
====
