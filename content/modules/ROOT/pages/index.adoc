从一个裸 GPU 节点出发，在 OpenShift AI 上，逐层构建一个受治理、可观测、经评测、有防护的 AI 服务——由你亲手完成。

本工作坊是为期三天的现场培训活动的实操环节。演示文稿负责讲解产品，实验则让你动手构建。在你自己的 OpenShift 集群上，使用一块 NVIDIA L4 GPU，每一个资源都由你亲自编写和应用：GPU 驱动与动态资源分配（DRA）、模型注册表与模型服务器、llm-d、模型即服务（Models-as-a-Service）、链路追踪、评测以及安全防护。每个步骤都明确告知你操作完成后的预期状态，并要求你与集群实际报告的结果进行比对。完成后，你不仅能向客户解释 OpenShift AI 能做什么，还能说明每一层是如何做到的以及如何验证。

实验按以下任务逐步推进：

. 使用 NVIDIA 驱动和 Kubernetes DRA 使 GPU 可被调度，并以独占和共享方式申请使用（第一天）。
. 查找已验证的模型，将其记录到模型注册表，并通过身份验证使用 vLLM 对外提供服务（第一天）。
. 用 llm-d 替代单个服务器，观察其调度器如何分发请求（第二天）。
. 搭建模型即服务，以分层、密钥、限额和使用量遥测的方式发布模型（第二天）。
. 使用 MLflow 追踪 Agent，评测模型，并用 NeMo Guardrails 进行安全防护（第三天）。

== 学习目标

完成本工作坊后，你将能够：

* 解释并演示 Kubernetes 工作负载如何通过 DRA 获取和共享 GPU。
* 将模型从目录经注册表接入，并部署到带身份验证的 vLLM 端点。
* 解释 llm-d 的调度器相比单个 vLLM 增加了哪些能力，并展示其路由过程。
* 搭建模型即服务，通过订阅、API 密钥和限速规则治理访问权限。
* 使用 MLflow、EvalHub 和 NeMo Guardrails 对模型支持的应用进行追踪、评测和防护。

== 技术模型

* *GPU 层：* NVIDIA 驱动使 GPU 在节点上可用；NVIDIA DRA 驱动将其发布为描述设备；Kubernetes 调度器将其分配给申请（ResourceClaim）。
* *模型层：* 模型目录列出已验证的模型；你的模型注册表记录你所使用的版本；KServe 运行 vLLM，将 GPU 显存转换为权重和 KV Cache。
* *路由层：* llm-d 的端点选择器根据服务器实时状态，为每个请求选择合适的副本。
* *服务层：* 模型即服务，由 Red Hat Connectivity Link（Kuadrant）在 Gateway API 网关上执行，将模型转变为带密钥、分层和限额的受治理内部服务。
* *信任层：* MLflow 追踪应用程序的操作记录，EvalHub 评测模型质量，NeMo Guardrails 决定哪些内容可以到达模型。

没有哪一层能单独回答客户的全部问题。GPU 申请不会对任何人进行身份验证，API 密钥无法证明模型的准确性，而基准测试也无法阻止恶意 prompt。本工作坊构建全部五层，让你能够展示每项保证的来源。
