= 模块 8：使用 EvalHub 评估模型
:navtitle: 模块 8：使用 EvalHub 评估模型

在第 1 天，模型自信地给出了关于 Kubernetes 的错误答案。每位客户最终都会问：_这个模型对我们有多好？我们怎么知道它何时变差？_ 仅凭几个手动输入的 prompt 来回答是轶闻，而非证据。评估则是针对固定的、带标签的基准以相同方式反复运行，并输出带不确定性的分数。

在本模块中，你将部署 EvalHub（OpenShift AI 的评估服务），了解它可以运行哪些评估，通过 API 密钥对你的 MaaS 模型运行标准基准测试，并解读分数的含义与局限。你会操作两次：通过 EvalHub 的 REST API 和仪表板的 *Evaluations* 页面，同时看到两者都是同一服务的客户端，且都将结果记录到 MLflow。

.初次接触模型评估？
[%collapsible]
====
* *EvalHub* — OpenShift AI 的评估编排器：一个 REST API，用于对模型端点运行基准任务并保存结果。
* *Provider（提供方）* — EvalHub 可以运行的评估框架，例如 `lm_evaluation_harness`（学术基准）或 `garak`（安全探测）。
* *Benchmark（基准）* — 一个带标签的任务；`arc_easy` 是一组小学科学选择题。
* *acc / acc_norm* — 答对问题的比例；`acc_norm` 对答案长度进行归一化处理。
* *Standard error（标准误差）* — 若换一组问题，分数可能变动的幅度；50 道题时标准误差较大。
====

== 技术背景

EvalHub 是每个 namespace 中的一个 `EvalHub` 资源。你以 JSON 格式将评估作为 Job 提交到其 REST API（每个 Job 没有对应的 CR）。对于 Job 中的每个基准，EvalHub 启动一个 Kubernetes Job，其适配器（此处为 LM Evaluation Harness）将基准问题发送给模型 URL 并对答案评分。Job 的 sidecar 从你在请求中指定的 Secret（`model.auth.secret_ref`）中注入模型凭证：MaaS 使用 `api-key`，以及用于信任其网关的 `ca_cert`。

由于模型在 MaaS 后面，评估自己的 token 会被计入其密钥所属订阅，与任何其他消费者一样。

Job 可以指定一个 MLflow 实验。EvalHub 会将每个基准的指标和参数作为 MLflow run 记录，使用你在模块 7 部署的 MLflow（工作空间 = 项目）。仪表板的 *Evaluations* 页面（技术预览版，默认关闭）是所选项目中 EvalHub 的客户端：它列出 Job，显示每个结果及其 MLflow run，比较 run，并通过相同 API 启动新 Job。

== 学习目标

* 部署 EvalHub，通过其 API 和仪表板探索可用的 provider 和基准。
* 使用存储在 Secret 中的 API 密钥对 MaaS 发布的模型运行基准测试。
* 解读分数及其标准误差，并说明分数不能证明什么。
* 演示错误密钥会导致评估明显失败，而非静默失败。
* 从仪表板运行相同评估，并在 MLflow 中比较两次 run。

== 练习 1：部署 EvalHub

.视频：在测试集群上运行本练习（等待时间已加速）
video::m8-ex1.mp4[width=100%]

[source,yaml]
----
kind: EvalHub
spec:
  tenancy: single                          # <1>
  database: {type: sqlite}                 # <2>
  providers: [lm-evaluation-harness, garak]   # <3>
  env:
  - name: MLFLOW_TRACKING_URI              # <4>
    value: https://mlflow.redhat-ods-applications.svc:8443/mlflow
----
<1> *tenancy: single* — 仅服务于当前 namespace（`multi` 服务于所有标记为租户的 namespace）。
<2> *database* — 必填；SQLite 将结果保存在 Pod 中（重启后丢失），PostgreSQL 持久保存结果。
<3> *providers* — 要提供的评估框架。
<4> *MLFLOW_TRACKING_URI* — EvalHub 记录结果的位置：你的 MLflow 的集群内地址，从其 status 中读取。operator 自己设置 MLflow 的 CA、token 和工作空间，但不设置此项；若未设置，指定了实验的 Job 会被拒绝（`mlflow_required_for_experiment`）。

[source,bash,role="execute"]
----
oc new-project ws-eval >/dev/null 2>&1 || oc project ws-eval
ML_URL=$(oc get mlflow mlflow -o jsonpath='{.status.address.url}')
oc apply -n ws-eval -f - <<EOF
apiVersion: trustyai.opendatahub.io/v1
kind: EvalHub
metadata:
  name: evalhub
spec:
  tenancy: single
  database:
    type: sqlite
  providers: [lm-evaluation-harness, garak]
  env:
  - name: MLFLOW_TRACKING_URI
    value: $ML_URL
EOF
until [ "$(oc get evalhub evalhub -n ws-eval -o jsonpath='{.status.phase}')" = Ready ]; do sleep 5; done
oc rollout status deploy/evalhub -n ws-eval --timeout=180s
oc get evalhub evalhub -n ws-eval -o jsonpath='phase {.status.phase}, providers {.status.activeProviders}{"\n"}'
oc get deploy evalhub -n ws-eval -o jsonpath='MLflow: {.spec.template.spec.containers[?(@.name=="evalhub")].env[?(@.name=="MLFLOW_TRACKING_URI")].value}{"\n"}'
oc get sa -n ws-eval | grep evalhub
# 仪表板的 Evaluations 页面（技术预览版）默认关闭：开启它
oc patch odhdashboardconfig odh-dashboard-config -n redhat-ods-applications --type merge \
  -p '{"spec":{"dashboardConfig":{"disableLMEval":false}}}'
----

预期结果：约 20 秒内，`deployment "evalhub" successfully rolled out`，`phase Ready, providers ["lm-evaluation-harness","garak"]`，`MLflow: https://mlflow.redhat-ods-applications.svc:8443/mlflow`，两个 ServiceAccount：`evalhub-service`（API 服务器）和 `evalhub-ws-eval-job`（评估 Job 使用的身份），以及 `odh-dashboard-config patched`。

打补丁约一分钟后，OpenShift AI 仪表板显示 *Develop & train* → *Evaluations*（标注 *Tech Preview*）。打开它并选择项目 `ws-eval`。

预期结果：*No evaluation runs*（如果重新运行本模块，显示之前的运行记录）和 *Start evaluation run* 按钮。若所选项目中没有 EvalHub，同一页面显示 *Evaluations unavailable*：它没有自己的数据，它是你刚部署的 EvalHub 的客户端。

== 练习 2：它能运行什么？

.视频：在测试集群上运行本练习（等待时间已加速）
video::m8-ex2.mp4[width=100%]

[source,bash,role="execute"]
----
{ cat /etc/pki/tls/certs/ca-bundle.crt; oc get configmap default-ingress-cert -n openshift-config-managed -o jsonpath='{.data.ca-bundle\.crt}'; } > ~/ingress-ca.crt
export CURL_CA_BUNDLE=~/ingress-ca.crt
EH=https://$(oc get route evalhub -n ws-eval -o jsonpath='{.spec.host}')
H=(-H "Authorization: Bearer $(oc whoami -t)" -H "X-Tenant: ws-eval")
curl -s -o /dev/null -w 'health (no token): %{http_code}\n' "$EH/api/v1/health"
curl -s -o /dev/null -w 'jobs   (no token): %{http_code}\n' "$EH/api/v1/evaluations/jobs"
curl -s "${H[@]}" "$EH/api/v1/evaluations/providers" | jq -r '.items[] | "\(.resource.id): \(.benchmarks | length) benchmarks"'
curl -s "${H[@]}" "$EH/api/v1/evaluations/providers" | jq -r '.items[] | select(.resource.id == "lm_evaluation_harness") | .benchmarks[] | select(.id == "arc_easy") | {id, description}'
----

预期结果：`health (no token): 200` 和 `jobs (no token): 401`；`lm_evaluation_harness: 188 benchmarks` 和 `garak: 9 benchmarks`；以及 `arc_easy` 条目，描述为"测试基础推理和科学知识的小学科学题（AI2 推理挑战，简单分组）。"

在仪表板中查看同样的目录：在 *Evaluations* 页面点击 *Start evaluation run*，然后点击 *Benchmark*。

预期结果：`197` 个基准（188 + 9），可按类别筛选。`arc_easy` 是 *Basic science Q&A* 卡片（类别 *Reasoning*，指标 `acc` 和 `acc_norm`），描述如上。点击 *Evaluations* 面包屑退出而不启动任何内容；练习 6 将回到这里。

== 练习 3：评估 MaaS 模型

.视频：在测试集群上运行本练习（等待时间已加速）
video::m8-ex3.mp4[width=100%]

Job 的凭证存储在 Secret 中：金 API 密钥，以及签署 MaaS 网关证书的 CA。Job 还指定了一个 MLflow 实验 `granite-evals`，EvalHub 将结果记录到其中。该代码块首先检查你在第 2 天生成的金密钥是否仍然有效，如已过期或终端丢失则重新生成（Web Terminal 的家目录重启后不会保留）。

[source,bash,role="execute",subs="attributes+"]
----
MAAS=https://maas.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
code=$(curl -s -o /dev/null -w '%\{http_code}' -H "Authorization: Bearer $(cat ~/key-gold 2>/dev/null)" "$MAAS/maas-api/v1/models")
if [ "$code" != 200 ]; then  # 已过期或终端重启丢失：重新生成（同模块 7）
  echo "gold key not usable (HTTP $code): minting a new one"
  resp=$(curl -s -X POST "$MAAS/maas-api/v1/api-keys" -H "Authorization: Bearer $(oc whoami -t)" -H 'Content-Type: application/json' \
    -d '{"name":"workshop-gold-m8","expiresIn":"72h","subscription":"granite-gold"}')
  key=$(jq -r '.key // empty' <<<"$resp")
  case "$key" in sk-oai-*) printf '%s' "$key" > ~/key-gold ;; *) echo "minting failed: $resp" ;; esac
fi
oc create secret generic maas-model -n ws-eval --from-literal=api-key="$(cat ~/key-gold)" \
  --from-file=ca_cert=$HOME/ingress-ca.crt --dry-run=client -o yaml | oc apply -f -
MAAS_URL=https://maas.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')/{model_namespace}/{model_name}/v1
submit() {  # submit <job name> <secret>
  jq -n --arg n "$1" --arg u "$MAAS_URL" --arg s "$2" '{name: $n,
    model: {url: $u, name: "{model_name}", auth: {secret_ref: $s}}, experiment: {name: "granite-evals"},
    benchmarks: [{id: "arc_easy", provider_id: "lm_evaluation_harness",
      parameters: {num_examples: 50, num_few_shot: 0, tokenizer: "ibm-granite/granite-4.0-h-tiny"}}]}' |
  curl -s "${H[@]}" -H 'Content-Type: application/json' -X POST "$EH/api/v1/evaluations/jobs" -d @- > ~/eval-submit.json
  jq -er '.resource.id // empty' ~/eval-submit.json || { echo "submission refused: $(cat ~/eval-submit.json)" >&2; return 1; }
}
await() {  # await <job id>：轮询直到 Job 结束，然后打印状态和结果
  [ -n "$1" ] || { echo "no job id: the submission failed" >&2; return 1; }
  for i in $(seq 1 90); do   # 最多等待 15 分钟
    state=$(curl -s "${H[@]}" "$EH/api/v1/evaluations/jobs/$1" | jq -r '.status.state // "unknown"' 2>/dev/null)
    case "$state" in
      completed|failed|cancelled|partially_failed) break ;;
      pending|running) sleep 10 ;;
      *) echo "job $1 not readable (state: $state); is it deleted, or is your token expired?" >&2; return 1 ;;
    esac
  done
  case "$state" in completed|failed|cancelled|partially_failed) ;; *) echo "job $1 still $state after 15 minutes" >&2; return 1 ;; esac
  curl -s "${H[@]}" "$EH/api/v1/evaluations/jobs/$1" | jq '{state: .status.state, error: .status.benchmarks[0].error_message.message,
    metrics: .results.benchmarks[0].metrics, test: .results.test, mlflow_experiment: .resource.mlflow_experiment_id}'
}
Q=https://$(oc get route thanos-querier -n openshift-monitoring -o jsonpath='{.spec.host}')/api/v1/query
gold_tokens() { curl -s -G -H "Authorization: Bearer $(oc whoami -t)" "$Q" \
  --data-urlencode 'query=sum(authorized_hits{subscription="granite-gold"})' | jq -r '.data.result[0].value[1] // "0"'; }
----

预期结果：仅在你的第 2 天密钥不可用时显示 `gold key not usable … minting a new one`，以及 `secret/maas-model created`。该代码块定义了 `submit`、`await` 和 `gold_tokens`，供本模块后续使用。

现在统计金订阅目前已消耗的 token，提交 Job 并等待结果：

[source,bash,role="execute"]
----
GOLD_BEFORE=$(gold_tokens); echo "gold tokens before: $GOLD_BEFORE"
JOB=$(submit granite-arc-easy maas-model) && echo "job $JOB"
oc get jobs -n ws-eval
await "$JOB"
----

预期结果：金订阅的当前 token 数、一个 Job ID、`ws-eval` 中的 Kubernetes Job（`Running`），约两分钟后显示 `"state": "completed"`、`"error": null`、指标 `"acc": 0.56`、`"acc_norm": 0.56`、`"acc_stderr": 0.0709…`，`test` 块 `{"score": 0.56, "threshold": 0.5, "pass": true}`，以及 `"mlflow_experiment"` 包含 EvalHub 创建的 `granite-evals` 实验 ID。

数字的含义：模型在 50 道简单科学题中答对约 56%，标准误差约 7 个百分点，因此在另外 50 道题上重新运行可能得到约 0.42 至 0.70 的分数。测试集群内部端点的相同基准得分为 0.60：相同模型，在不确定性范围内。`test` 判断将分数与默认阈值 0.5 比较；这是你为自己的用例设置的门槛，不是质量认证。

在仪表板中查看同一次运行：在 *Evaluations* 页面（项目 `ws-eval`），点击 `granite-arc-easy`。

预期结果：列表中 `granite-arc-easy` 状态为 `Complete`，结果为 `56%`。其页面显示评估分数 `56%`、判定 `Pass` 和主要指标 `acc`，下方是 EvalHub 记录的 MLflow run：指标 `acc`、`acc_stderr`、`acc_norm`、`acc_norm_stderr` 和 `overall_score`，参数（`benchmark_id`、`provider_id`、`model_name`、`num_examples_evaluated` `50`、`duration_seconds`），以及在 *About this run* 下显示的实验 ID 和 run ID。页面显示 *Benchmark threshold* 为 `0.25`，这是目录为此基准建议的默认值；你 Job 的 `test` 块使用的是 `0.5`。当你设置分数门槛时，请自己指定阈值（练习 6 会操作这一步）。

== 练习 4：错误密钥（负控实验）

.视频：在测试集群上运行本练习（等待时间已加速）
video::m8-ex4.mp4[width=100%]

[source,bash,role="execute"]
----
oc create secret generic maas-model-bad -n ws-eval --from-literal=api-key=sk-oai-not-a-real-key \
  --from-file=ca_cert=$HOME/ingress-ca.crt --dry-run=client -o yaml | oc apply -f -
BAD=$(submit granite-arc-easy-badkey maas-model-bad) && await "$BAD"
----

预期结果：`"state": "failed"`，`"error": "Model endpoint returned HTTP 403: 403 Client Error: Forbidden for url: https://maas.…/{model_namespace}/{model_name}/v1/completions"`，且没有指标。MaaS 对未知密钥返回 403（完全不带密钥的请求得到 401）。评估明显失败，而非输出一个分数。

== 练习 5：评估本身也是 MaaS 的消费者

.视频：在测试集群上运行本练习（等待时间已加速）
video::m8-ex5.mp4[width=100%]

将金订阅的 token 数与评估前统计的数量进行比较。Prometheus 约每 30 秒抓取一次，因此循环等待新值：

[source,bash,role="execute"]
----
for i in $(seq 1 12); do [ "$(gold_tokens)" != "$GOLD_BEFORE" ] && break; sleep 15; done   # 最多等待 3 分钟
echo "gold tokens: before $GOLD_BEFORE, now $(gold_tokens), charged by the evaluation: $(( $(gold_tokens | cut -d. -f1) - ${GOLD_BEFORE%%.*} ))"
----

预期结果：`gold tokens: before …, now …, charged by the evaluation: …`，大约消耗 6,000 个 token（测试集群上为 6,314）：50 道基准题以带选项的 completion 形式发送，像任何其他消费者一样被计入金订阅。（错误密钥的运行未消耗 token：MaaS 在模型处理之前就拒绝了它。）

== 练习 6：从仪表板运行相同评估

.视频：在测试集群上运行本练习（等待时间已加速）

向导构建的 Job 与你用 `jq` 构建的相同。打印端点以备粘贴：

[source,bash,role="execute"]
----
echo "Endpoint URL: $MAAS_URL"

在 *Evaluations* 页面（项目 `ws-eval`）：

. 点击 *Start evaluation run* → *Benchmark*，在 *Basic science Q&A* 卡片上点击 *Select benchmark*。

. *Source*：`Model`。*Model*：`Other (External endpoint)`。*Model name*：`{model_name}`。*Endpoint URL*：粘贴上方打印的 URL。*API key secret name*：`maas-model`，即练习 3 中创建的 Secret。
. 点击 *Validate connection*。预期结果：*Connection established successfully*。该检查通过 MaaS 使用 Secret 中的密钥和 CA 调用端点。
. *Benchmark threshold*：`50`。选择 *Benchmark parameters* 并输入 `{"num_examples": 50, "num_few_shot": 0, "tokenizer": "ibm-granite/granite-4.0-h-tiny"}`，与你的 API Job 参数相同。

预期结果：列表中 `granite-arc-easy-gui` 显示为 `Pending`，紧挨着你之前的运行记录。现在通过相同 API 在终端中跟踪它：

[source,bash,role="execute"]
----
GUI_JOB=$(curl -s "${H[@]}" "$EH/api/v1/evaluations/jobs" | jq -r '.items[] | select(.name == "granite-arc-easy-gui") | .resource.id' | head -1)
await "$GUI_JOB"
curl -s "${H[@]}" "$EH/api/v1/evaluations/jobs" | jq -r '.items[] | "\(.name)  \(.status.state)  acc=\(.results.benchmarks[0].metrics.acc // "-")  mlflow_experiment=\(.resource.mlflow_experiment_id // "-")"'
----

预期结果：约两分钟后 `"state": "completed"`，指标与练习 3 相同（`"acc": 0.56`、`"acc_stderr": 0.0709…`），`test` 块中 `"threshold": 0.5`（你设置的 50）和 `"pass": true`；然后每个 Job 一行：`granite-arc-easy-gui` 和 `granite-arc-easy` 状态 `completed`，`acc=0.56`，相同 `mlflow_experiment`，`granite-arc-easy-badkey` 状态 `failed`，`acc=-`。

回到 *Evaluations* 页面，选中 `granite-arc-easy-gui` 和 `granite-arc-easy`，点击 *Compare*。

预期结果：*Comparing granite-arc-easy-gui and granite-arc-easy*（顺序任意）：MLflow 的 run 对比视图，显示 `acc` 和 `duration_seconds` 的图表，两次运行都在实验 `granite-evals` 中，参数并排比较。相同模型，相同 50 道题，相同分数：无论从仪表板还是用 `curl` 启动，都是同一个 EvalHub Job。

== 验证检查点

继续之前，确保你能回答以下问题：

* 如何向 EvalHub 提交评估，实际执行的是什么？
* 评估如何向模型认证，凭证存放在哪里？
* 50 道题上 `acc 0.56 ± 0.07` 允许你声明什么，不允许声明什么？
* 为什么错误密钥导致 Job 失败是有价值的？
* 仪表板向导与你的 `jq` Job 分别向 EvalHub 发送了什么，两个结果最终存在哪里？

.答案
[%collapsible]
====
* 以 JSON 格式 POST 到 `/api/v1/evaluations/jobs`（带 token 和 `X-Tenant` 请求头）；EvalHub 为每个基准启动一个 Kubernetes Job，其中 provider 的适配器查询模型并评分。
* Job 的 sidecar 读取 `model.auth.secret_ref` 中指定的 Secret：`api-key`（金 MaaS 密钥）用于 `Authorization` 请求头，`ca_cert` 用于验证网关。
* 在此样本上，模型能正确回答约一半至三分之二的简单科学题。不能证明它对你的领域准确、安全，或比标准误差范围内分数更高的其他模型更好。
* 静默回退会为其他内容生成分数，或根本不生成分数，而没有人注意到；失败的 Job 是可见且可告警的。
* 相同的 Job JSON 发送到相同的 API（`model.url`、`model.name`、`auth.secret_ref`、基准及其参数、`experiment.name`），外加你选择的主要指标和阈值。两次运行都是 `ws-eval` 中的 EvalHub Job，都是实验 `granite-evals` 中的 MLflow run。
====
