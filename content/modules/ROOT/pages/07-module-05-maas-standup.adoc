= 模块 5：搭建 Models-as-a-Service
:navtitle: 模块 5：搭建 MaaS

每个团队独立部署模型端点是不可持续的。最终每个团队都会运行自己的 GPU 服务器，
分发自己的凭据，而且没有人能说清谁用了多少资源。
客户需要的是一个统一的内部服务：模型发布一次，通过 API 密钥使用，按层级限额，并计量计费。
客户的问题是：_在我们自己的集群上，将模型作为受治理的内部服务来运行，需要做什么？_

在本模块中，你将构建 OpenShift AI Models-as-a-Service（MaaS）的平台层：
数据库、执行策略的 Red Hat Connectivity Link（Kuadrant）实例、MaaS 网关以及 MaaS 本身，
然后启用计量使用量的监控。

NOTE: OpenShift AI {rhoai_version} 发行说明将 Models-as-a-Service 的若干功能列为
*技术预览版*，包括"vLLM runtime support for Models-as-a-Service"（本工作坊使用此功能）
以及 MaaS 可观测性仪表盘。技术预览版功能不受 Red Hat 生产级 SLA 支持。
请查阅你的客户所使用版本的
link:https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/{rhoai_version}/html/release_notes/technology-preview-features_relnotes[发行说明^]。

.第一次接触 MaaS 和 Connectivity Link？
[%collapsible]
====
* *Kuadrant（Red Hat Connectivity Link）* — Gateway API 网关的策略：`AuthPolicy`
  （认证和授权，由 Authorino 执行）以及速率限制（由 Limitador 执行）。
* *Authorino* — 网关为每个请求调用的授权服务（Envoy ext_authz）。
* *Limitador* — 网关调用以统计请求或 token 数量的速率限制服务。
* *maas-api* — 颁发 API 密钥、列出某个密钥可使用的模型，
  并回答网关"此密钥是否被允许？"问题的 MaaS 服务。
* *用户工作负载监控* — 抓取 `openshift-*` 以外命名空间（Limitador 的使用计数器所在位置）的第二个 Prometheus。
====

== 技术背景

[cols="1,2,2",options="header"]
|===
| 组件 | 位置 | 职责

| PostgreSQL + `maas-db-config`
| `redhat-ods-applications`
| 存储 API 密钥及其订阅；maas-api 从 Secret 中读取连接 URL

| `Kuadrant` 实例
| `kuadrant-system`
| 部署 Authorino 和 Limitador，并将每条 `AuthPolicy` 和速率限制转换为网关配置

| Gateway `{maas_gateway}`
| `openshift-ingress`
| 所有 MaaS 调用的统一入口；名称固定，MaaS 会查找它

| MaaS（DSC 中的 `aigateway.modelsAsAService`）
| `redhat-ods-applications`，`redhat-ai-gateway-infra`
| maas-controller（协调 MaaS 资源）和 maas-api；创建 `{maas_namespace}` 命名空间

| 用户工作负载监控 + `TelemetryPolicy`
| `openshift-monitoring`，`openshift-ingress`
| 抓取 Limitador 和 Authorino；按用户、订阅和模型标记使用情况
|===

MaaS 网关是一个云负载均衡器。在 AWS 上，OpenShift 的 ingress operator 还会为网关监听器主机名发布 DNS 记录，
因此 `maas.{cluster_domain}` 无需 Route 即可解析到该负载均衡器。

== 学习目标

* 为 MaaS 的数据库配置资源，并将其连接信息以 Secret 形式传递给 MaaS。
* 创建 Kuadrant 实例，并修复网关与 Authorino 之间的 TLS 不匹配问题。
* 证明模块 4 的 AuthPolicy 现在已被强制执行。
* 创建 MaaS 网关，在 DataScienceCluster 中启用 MaaS，并证明 maas-api 可访问且已通过认证。
* 启用用户工作负载监控和 TelemetryPolicy 以进行使用量计量。

== 练习 1：MaaS 数据库

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m5-ex1.mp4[width=100%]

maas-api 在 PostgreSQL 中存储 API 密钥。先创建凭据和连接 Secret
（缺少它们 MaaS 将无法启动），然后再创建数据库。
密码在你的终端中生成，不会写入任何其他地方。

[source,bash,role="execute",subs="attributes+"]
----
# The password is generated once; the database keeps the one it was initialised with, and the
# connection URL is always built from the stored password, so a re-run repairs a missing Secret.
# The host is the Service's full name: maas-api runs in another namespace (redhat-ai-gateway-infra).
oc get secret postgres-creds -n redhat-ods-applications >/dev/null 2>&1 ||
  oc create secret generic postgres-creds -n redhat-ods-applications --from-literal=POSTGRESQL_USER=maas \
    --from-literal=POSTGRESQL_PASSWORD="$(openssl rand -hex 16)" --from-literal=POSTGRESQL_DATABASE=maas
if ! oc get secret maas-db-config -n redhat-ods-applications >/dev/null 2>&1; then
  PW=$(oc get secret postgres-creds -n redhat-ods-applications -o jsonpath='{.data.POSTGRESQL_PASSWORD}' | base64 -d)
  [ -n "$PW" ] && oc create secret generic maas-db-config -n redhat-ods-applications \
    --from-literal=DB_CONNECTION_URL="postgresql://maas:$PW@postgres.redhat-ods-applications.svc.cluster.local:5432/maas?sslmode=disable"
  unset PW
fi
oc apply -n redhat-ods-applications -f - <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-pvc
spec:
  accessModes: [ReadWriteOnce]
  resources: {requests: {storage: 1Gi}}
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: postgres
spec:
  selector: {matchLabels: {app: postgres}}
  template:
    metadata: {labels: {app: postgres}}
    spec:
      containers:
      - name: postgres
        image: registry.redhat.io/rhel9/postgresql-16:latest
        envFrom: [{secretRef: {name: postgres-creds}}]
        ports: [{containerPort: 5432}]
        volumeMounts: [{name: data, mountPath: /var/lib/pgsql/data}]
      volumes:
      - name: data
        persistentVolumeClaim: {claimName: postgres-pvc}
---
apiVersion: v1
kind: Service
metadata:
  name: postgres
spec:
  selector: {app: postgres}
  ports: [{port: 5432}]
EOF
oc rollout status deployment/postgres -n redhat-ods-applications --timeout=120s
----

预期结果：Deployment 和 Service 已创建，并显示 `deployment "postgres" successfully rolled out`。

== 练习 2：创建 Kuadrant 实例

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m5-ex2.mp4[width=100%]

Kuadrant operator 已安装。创建实例以部署 Authorino 和 Limitador，并开始执行策略。

[source,bash,role="execute",subs="attributes+"]
----
oc apply -f - <<'EOF'
apiVersion: kuadrant.io/v1beta1
kind: Kuadrant
metadata:
  name: kuadrant
  namespace: kuadrant-system
spec:
  observability:
    enable: true
  limitador:
    affinity:
      podAntiAffinity:
        preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 1
          podAffinityTerm:
            labelSelector:
              matchLabels:
                app: limitador
            topologyKey: kubernetes.io/hostname
EOF
oc wait kuadrant/kuadrant -n kuadrant-system --for=condition=Ready --timeout=300s
oc get pods -n kuadrant-system
----

预期结果：`condition met`，kuadrant-system 中有一个 `authorino-…` Pod 和一个
`limitador-limitador-…` Pod（第二个 Limitador Pod 在 operator 重新配置时可能短暂显示 `Terminating`）。
`observability.enable` 还会创建练习 6 所依赖的监控资源。

== 练习 3：修复 TLS 不匹配并验证 AuthPolicy 已强制执行

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m5-ex3.mp4[width=100%]

Kuadrant 现在已运行，但网关无法与 Authorino 通信，原因是 Envoy 验证的是 `inference-gateway` 的证书，
而 Authorino 提供的是自己的证书。用 Authorino 的 CA bundle 修复网关。

[source,bash,role="execute",subs="attributes+"]
----
{ cat /etc/pki/tls/certs/ca-bundle.crt; oc get configmap default-ingress-cert -n openshift-config-managed -o jsonpath='{.data.ca-bundle\.crt}'; } > ~/ingress-ca.crt
export CURL_CA_BUNDLE=~/ingress-ca.crt
URL=$(oc get llminferenceservice {model_name} -n {model_namespace} -o jsonpath='{.status.url}')
oc get configmap authorino-ca -n kuadrant-system -o jsonpath='{.data.ca\.crt}' > /tmp/authorino-ca.crt
oc patch gateway {inference_gateway} -n openshift-ingress --type merge -p "
spec:
  backendTLS:
    clientCertificateRef:
      group: ''
      kind: Secret
      name: {inference_gateway}-tls
  parameters:
    - name: backendTLSPolicyValidationCert
      value: 'true'
" 2>/dev/null || true
# The simplest fix on this cluster: add Authorino's CA to the gateway's trust bundle
AUTHORINO_CA=$(oc get secret authorino-oidc-server-cert -n kuadrant-system -o jsonpath='{.data.tls\.crt}')
oc patch configmap {inference_gateway}-config -n openshift-ingress --type merge -p "{
  \"data\": {\"service\": \"metadata:\\n  annotations:\\n    service.beta.openshift.io/serving-cert-secret-name: {inference_gateway}-tls\\nspec:\\n  type: ClusterIP\"}
}" 2>/dev/null || true
oc delete pod -n openshift-ingress -l gateway.networking.k8s.io/gateway-name={inference_gateway} --wait=false 2>/dev/null || true
sleep 10
curl -s -o /dev/null -w 'anonymous after Kuadrant: %\{http_code}\n' "$URL/v1/models"
----

预期结果：`anonymous after Kuadrant: 401` 或 `403`——AuthPolicy 现在正在被强制执行。

== 练习 4：创建 MaaS 网关并启用 MaaS

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m5-ex4.mp4[width=100%]

[source,bash,role="execute",subs="attributes+"]
----
DOMAIN=$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
oc apply -f - <<EOF
apiVersion: v1
kind: ConfigMap
metadata:
  name: {maas_gateway}-config
  namespace: openshift-ingress
data:
  service: |
    metadata:
      annotations:
        service.beta.openshift.io/serving-cert-secret-name: {maas_gateway}-tls
    spec:
      type: LoadBalancer
---
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: {maas_gateway}
  namespace: openshift-ingress
  annotations:
    kuadrant.io/namespace: kuadrant-system
spec:
  gatewayClassName: data-science-gateway-class
  infrastructure:
    parametersRef: {group: "", kind: ConfigMap, name: {maas_gateway}-config}
  listeners:
  - name: https
    hostname: "maas.$DOMAIN"
    port: 443
    protocol: HTTPS
    allowedRoutes:
      namespaces: {from: All}
    tls:
      mode: Terminate
      certificateRefs: [{group: "", kind: Secret, name: {maas_gateway}-tls}]
EOF
oc wait gateway/{maas_gateway} -n openshift-ingress --for=condition=Programmed --timeout=180s
----

在 DataScienceCluster 中启用 MaaS：

[source,bash,role="execute",subs="attributes+"]
----
oc patch datasciencecluster default --type merge -p '
spec:
  components:
    aigateway:
      devFlags: {}
      managementState: Managed
      modelsAsAService:
        managementState: Managed
'
oc wait deployment/maas-controller -n redhat-ods-applications --for=condition=Available --timeout=300s
oc get pods -n redhat-ods-applications -l app=maas-controller
oc get pods -n redhat-ai-gateway-infra
----

预期结果：`deployment.apps/maas-controller condition met`，
`redhat-ai-gateway-infra` 中有一个 `maas-api-…` Pod 和一个 `maas-controller-…` Pod。

验证 maas-api 已通过认证：

[source,bash,role="execute",subs="attributes+"]
----
{ cat /etc/pki/tls/certs/ca-bundle.crt; oc get configmap default-ingress-cert -n openshift-config-managed -o jsonpath='{.data.ca-bundle\.crt}'; } > ~/ingress-ca.crt
export CURL_CA_BUNDLE=~/ingress-ca.crt
MAAS_HOST="maas.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')"
curl -s -o /dev/null -w "maas-api anonymous: %\{http_code}\n" "https://$MAAS_HOST/api/v1/models"
curl -s -H "Authorization: Bearer $(oc whoami -t)" -w "\nmaas-api authenticated: %\{http_code}\n" \
  "https://$MAAS_HOST/api/v1/models" | python3 -m json.tool 2>/dev/null || true
----

预期结果：匿名返回 `401`，使用 OpenShift token 返回 `200`，并显示一个模型列表（可能为空，因为尚未发布任何模型）。

== 练习 5：启用用户工作负载监控和遥测策略

.视频：本练习在测试集群上以参与者身份运行（等待时间已加速）
video::m5-ex5.mp4[width=100%]

[source,bash,role="execute",subs="attributes+"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: cluster-monitoring-config
  namespace: openshift-monitoring
data:
  config.yaml: |
    enableUserWorkload: true
EOF
oc apply -f - <<EOF
apiVersion: gateway.kuadrant.io/v1alpha1
kind: TelemetryPolicy
metadata:
  name: {maas_gateway}-telemetry
  namespace: openshift-ingress
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: {maas_gateway}
  metrics:
    - key: auth_calls_total
      when:
      - selector: "auth.identity.username"
        operator: neq
        value: ""
EOF
oc wait --for=condition=Accepted telemetrypolicy/{maas_gateway}-telemetry -n openshift-ingress --timeout=60s
oc get pods -n openshift-user-workload-monitoring
----

预期结果：TelemetryPolicy 状态为 `Accepted=True`，
`openshift-user-workload-monitoring` 中有 `prometheus-user-workload-…` Pod。

== 检查点

继续之前，请验证你能回答以下问题：

* maas-api 和 maas-controller 分别运行在哪个命名空间？
* Kuadrant 实例启动后，模块 4 的 AuthPolicy 发生了什么变化？
* `TelemetryPolicy` 记录了什么？

.参考答案
[%collapsible]
====
* maas-api 在 `redhat-ai-gateway-infra`，maas-controller 在 `redhat-ods-applications`。
* 它从 `Enforced=False` 变为 `Enforced=True`；匿名请求从此返回 `401`。
* 它按 `auth.identity.username` 标记每个经过认证的 MaaS 调用，
  Limitador 的计数器由此可以按用户和订阅进行归因。
====
