= 清理
:navtitle: 清理

仅执行与你完成进度相符的部分。每个代码块可以安全地重复执行。

== 参与者清理

从 Web Terminal 删除你在实验中创建的资源。首先查看将要删除的内容：

[source,bash,role="execute",subs="attributes+"]
----
oc get project {gpu_namespace} {model_namespace} --ignore-not-found
oc get modelregistries.modelregistry.opendatahub.io -n {registry_namespace} --ignore-not-found
oc get gpucluster,nvidiadriver --ignore-not-found
oc get nodefeaturediscovery -n openshift-nfd --ignore-not-found
----

预期结果：存在的资源中可能包括：项目 `{gpu_namespace}` 和 `{model_namespace}`（`Active`），`{registry_name}` 注册表（`AVAILABLE True`），`gpucluster.nvidia.com/gpu-cluster` 和 `nvidiadriver.nvidia.com/gpu-driver`（`ready`），以及 `nfd-instance`。

如果你完成了第 3 天的内容，先删除其项目和 MLflow。先查看：

[source,bash,role="execute",subs="attributes+"]
----
oc get project ws-agent ws-eval ws-guard --ignore-not-found
oc get mlflows.mlflow.opendatahub.io --ignore-not-found
oc get networkpolicy -n {model_namespace} --ignore-not-found
----

预期结果：存在的资源中可能包括：项目 `ws-agent`、`ws-eval` 和 `ws-guard`（`Active`），`mlflow` 追踪服务器（`AVAILABLE True`，版本 `3.14.0`），以及 NetworkPolicy `{model_name}-ingress`。

[source,bash,role="execute",subs="attributes+"]
----
oc delete project ws-agent ws-eval ws-guard --ignore-not-found --wait=true
oc delete networkpolicy {model_name}-ingress -n {model_namespace} --ignore-not-found
oc delete mlflows.mlflow.opendatahub.io mlflow --ignore-not-found --wait=true
oc patch datasciencecluster default-dsc --type merge -p '{"spec":{"components":{"mlflowoperator":{"managementState":"Removed"}}}}'
oc patch odhdashboardconfig odh-dashboard-config -n redhat-ods-applications --type merge \
  -p '{"spec":{"dashboardConfig":{"disableLMEval":null}}}'
rm -f ~/labelled.tsv
oc get project ws-agent ws-eval ws-guard --ignore-not-found
----

预期结果：项目、NetworkPolicy 和追踪服务器均已删除。评估结果随 `ws-eval` 项目一起删除；追踪记录不随 `ws-agent` 项目删除（MLflow 将其存储在自己的卷中，以工作空间名称为键），而是随追踪服务器及其卷一起删除。`default-dsc patched` 将 MLflow 设回 `Removed`（其 Pod 和卷在一分钟内消失），`odh-dashboard-config patched` 再次隐藏仪表板的 *Evaluations* 页面（模块 8 开启了它），最后一条命令无输出。

如果你完成了第 2 天的内容，先按相反顺序删除其组件（密钥、服务、平台）。先查看：

[source,bash,role="execute",subs="attributes+"]
----
oc get maasmodelref -n {model_namespace} --ignore-not-found; oc get maassubscription,maasauthpolicy -n {maas_namespace} --ignore-not-found
oc get gateway -n openshift-ingress {maas_gateway} {inference_gateway} --ignore-not-found
oc get kuadrant -n kuadrant-system --ignore-not-found; oc get deploy postgres -n redhat-ods-applications --ignore-not-found
oc get datasciencecluster default-dsc -o jsonpath='aigateway: {.spec.components.aigateway.managementState}{"\n"}'
----

预期结果：你创建的资源中可能包括：MaaSModelRef `{model_name}`（`Ready`），订阅 `granite-bronze` 和 `granite-gold` 以及认证策略 `granite-access`（`Active`），Gateway `{maas_gateway}` 和 `{inference_gateway}`（`PROGRAMMED True`），Kuadrant 实例 `kuadrant`，`postgres` Deployment（`1/1`），以及 `aigateway: Managed`。

[source,bash,role="execute",subs="attributes+"]
----
oc delete job maas-client -n {model_namespace} --ignore-not-found
oc delete maasmodelref {model_name} -n {model_namespace} --ignore-not-found
oc delete maassubscription granite-gold granite-bronze -n {maas_namespace} --ignore-not-found
oc delete maasauthpolicy granite-access -n {maas_namespace} --ignore-not-found
oc delete llminferenceservice {model_name} -n {model_namespace} --ignore-not-found --wait=true
oc delete maastenantconfigs.maas.opendatahub.io --all -n {maas_namespace} --ignore-not-found --wait=true
oc delete aitenants.maas.opendatahub.io --all -n ai-tenants --ignore-not-found --wait=true
oc delete deploy maas-api -n redhat-ai-gateway-infra --ignore-not-found --wait=true
oc patch datasciencecluster default-dsc --type merge \
  -p '{"spec":{"components":{"aigateway":{"managementState":"Removed","modelsAsAService":{"managementState":"Removed"}}}}}'
oc wait --for=delete deploy/maas-controller -n redhat-ods-applications --timeout=300s &&
  oc annotate configs.maas.opendatahub.io default maas.opendatahub.io/default-aitenant-bootstrapped-
oc delete namespace {maas_namespace} redhat-ai-gateway-infra ai-tenants --ignore-not-found --wait=true
oc delete resourceclaim shared-l4 -n {model_namespace} --ignore-not-found
oc patch odhdashboardconfig odh-dashboard-config -n redhat-ods-applications --type merge \
  -p '{"spec":{"dashboardConfig":{"modelAsService":false,"observabilityDashboard":false}}}'
oc delete telemetrypolicy maas-telemetry -n openshift-ingress --ignore-not-found
oc delete authpolicy maas-gateway-auth -n openshift-ingress --ignore-not-found
oc delete envoyfilter payload-processing -n openshift-ingress --ignore-not-found
oc delete gateway {maas_gateway} {inference_gateway} -n openshift-ingress --ignore-not-found
oc delete route {inference_gateway} -n openshift-ingress --ignore-not-found
oc delete configmap {inference_gateway}-config -n openshift-ingress --ignore-not-found
oc delete kuadrant kuadrant -n kuadrant-system --ignore-not-found --wait=true
oc delete namespace kuadrant-system --ignore-not-found --wait=true
oc delete deploy/postgres svc/postgres pvc/postgres-data secret/postgres-creds secret/maas-db-config -n redhat-ods-applications --ignore-not-found
rm -f ~/key-gold ~/key-bronze ~/ingress-ca.crt
oc get gateway -n openshift-ingress
----

预期结果：每个对象报告 `deleted`（若不存在则跳过），最后一条命令仅列出 `data-science-gateway`（OpenShift AI 自有的）。如果仅为本次工作坊启用了用户工作负载监控，请在 `cluster-monitoring-config` 中将 `enableUserWorkload: false`（如果是你创建的，也可删除该 ConfigMap）。

然后删除第 1 天的资源，先删除模型服务器和注册表，最后删除 GPU 栈：

[source,bash,role="execute",subs="attributes+"]
----
oc delete project {model_namespace} {gpu_namespace} --ignore-not-found --wait=true
oc delete modelregistries.modelregistry.opendatahub.io {registry_name} -n {registry_namespace} --ignore-not-found --wait=true
oc delete gpucluster gpu-cluster --ignore-not-found --wait=true
oc delete nvidiadriver gpu-driver --ignore-not-found --wait=true
oc delete nodefeaturediscovery nfd-instance -n openshift-nfd --ignore-not-found --wait=true
oc get deviceclass -o name | grep nvidia || echo "no NVIDIA device classes"
----

预期结果：删除完成，最后一行打印 `no NVIDIA device classes`：DRA 栈和驱动已移除。NFD 在节点上设置的标签（`feature.node.kubernetes.io/…`）会一直保留，直到有人手动删除，因此模块 1 中"无 NVIDIA PCI 标签"的检查现在会打印 `true`。

WARNING: 删除运行 Web Terminal 的项目会关闭终端。Web Terminal 运行在自己的项目中（默认为 `openshift-terminal`），因此上述命令不会影响它。

== 负责人清理

只有部署环境的人才能在本仓库 checkout 的集群管理员 shell 中执行此操作。先查看将要删除的内容：每个列出的 Application，以及它创建的 operator 和 namespace。

[source,bash,subs="attributes+"]
----
make -C automation status
oc get namespace {showroom_namespace} nvidia-gpu-operator openshift-nfd --ignore-not-found
----

然后删除并确认 Showroom namespace 已消失：

[source,bash,subs="attributes+"]
----
make -C automation teardown
oc get namespace {showroom_namespace} --ignore-not-found
----

删除完成后，最后一条命令无输出。

列出剩余资源：

[source,bash]
----
oc get csv -A --no-headers | awk '{print $1, $2}' | sort -u -k2,2 | grep -E 'nfd|gpu-operator-certified|rhcl-operator|web-terminal|devworkspace|authorino|limitador|dns-operator'
----

若需要为下次课程复用集群，还需删除 NFD 在节点上设置的标签：

[source,bash]
----
oc get nodes -o json | jq -r '.items[] | .metadata.name as $n | .metadata.labels | keys[] | select(startswith("feature.node.kubernetes.io/")) | "\($n) \(.)"' | sort | uniq | head
for n in $(oc get nodes -o name); do
  l=$(oc get "$n" -o json | jq -r '.metadata.labels | keys[] | select(startswith("feature.node.kubernetes.io/pci-")) | . + "-"')
  [ -z "$l" ] || oc label "$n" $l
done
----
